# ba-lab

This repo designs a business analysis (BA) method for agentic coding: from a fuzzy request or idea to an accepted solution.

## Layers

- The BA method is the product.
- nanoba is a possible tool for parts of the method. Do not design it until the method's analysis of the need says what it is.
- Our way of working (this file, the friction log, the study) supports the work. It is not the product.

## Working agreements

- Give each chat one goal and a stated outcome. End the chat with a handover that names the next chat's goal.
- Design from scratch. Treat existing skills and tools (bootstrapping-apps, OpenSpec, and others) as inspiration, not as a baseline.
- Try every step on two cases: webplatform (client work) and Claude Loadout (own project). If a step fits only one case, it does not generalize yet.
- You may name private and client projects in this repo's files, because the repo is private and those projects are its test material. This overrides the global rule against private names in project files.
- Mark a provisional answer as provisional. Revisit it when the method answers the question.
- Ground every term and practice in an official or original source, and cite it. If no official definition exists, say so before you define one.

## Learning

The user learns BA while building the method.

- Before you teach, assess the user's level per area on this scale: 0 never heard of it, 1 know the name, 2 can explain it roughly, 3 can explain it in detail, 4 can also say when it fails or does not fit.
- Teach only the concepts the current chat's goal needs.
- Introduce one concept per step, with at most three new terms. Introduce every organisation and acronym at first use.
- Suggest the full source to read. Do not summarise it in its place.
- End a teaching step with one explain-back question, as the last line.
- Ask one question per reply. Keep readings and note ideas in a parked list, and show it when the user asks.
- Before a phase closes, check each concept that emerged. It needs an explain-back rated 3 or higher, and a zettelkasten note if the user wants one.

## Files

- `friction-log.md`: every moment where a method or a tool did not fit. It decides which technique comes next.
